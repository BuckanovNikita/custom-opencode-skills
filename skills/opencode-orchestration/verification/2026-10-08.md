## Independent scenario evaluation

Native review agents were requested as GPT-6.1 Sol at medium effort with fresh
contexts, read-only assignments, and no further delegation. These authoring agents
were not the three target models; requested settings are not independent runtime
telemetry.

Before drafting, a baseline exercise covered a shared evaluation module, occupied
GPU, changed evaluation split, passing unit tests, unsupported task arguments, and
an unrelated long worker context. The baseline already handled these risks; no
behavioral failure or improvement attributable to the new skill was established.

After drafting, a fresh agent applied the package to these scenarios:

| Scenario | Observed instruction-level response |
| --- | --- |
| Metric fix plus optimization sharing a file/GPU | Serialize ownership, preserve existing job, require matched baseline, reject unsupported gain |
| Missing Qwen agent and serial-only host | Disclose limitation, use supported arguments, avoid silent substitution or manufactured concurrency |
| Conflicting findings, NaNs, stale review, interrupted writes | Reproduce against current state, inspect partial writes, fix and review final changes |
| DeepSeek context pressure and Qwen thinking request | Preserve protocol-required state, use fresh handoff, avoid unsupported thinking controls |
| Reviewer requests test execution | Keep reviewer read-only; coordinator executes authorized checks |
| Trivial docstring edit | Parent handles directly with proportional verification |

These were tabletop responses, not executed ML experiments or a quantitative
prompt-quality benchmark. The exercise exposed no blocking ambiguity.

A separate fresh reviewer inspected the eight instruction/example files and their
official sources after parent verification, returning `ship` with no blocking
findings. This record was added afterward; the DeepSeek identity citation was also
changed to the verified API overview without changing its claim.
